# Command Policy

Five tiers. Allowed = Read + Local + Shared. Forbidden rules cannot be lifted by project convention or by user instruction; Restricted actions run only after the user explicitly asks for them in the current conversation and the pre-check passes.

## 1. Tiers

| Tier           | Operations                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Permission                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------- |
| **Read**       | `status`, `log`, `diff`, `show`, `blame`, `reflog`, `branch --list`/`--show-current`, `worktree list`, `stash list`, `tag --list`, `remote -v`/`remote show`, `symbolic-ref`, `rev-parse`, `describe`, `merge-base`, `check-ref-format`, `ls-remote`, `clean -n`, other read-only inspection commands, and `fetch`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | Automatic                                          |
| **Local**      | `switch`; create a branch or worktree from trunk (`--no-track`); `add` by path; `commit`; `amend`/`fixup` only under `commit-convention.md` §8; `restore --staged` only for explicit in-scope paths after reviewing the index; pre-existing user paths may be unstaged only when the user explicitly authorized that work (for example, W6), and no out-of-scope paths may be touched; `restore` of changes the agent made or a verified source path under W13 after preserving current state; create a recovery branch at a verified SHA only under W13; `reset --soft` on the agent's own unpublished commits; `reset --mixed` on the agent's own unpublished commits only when no pre-existing user-staged changes are in the index; `stash` of changes the agent made; `merge`/`rebase` of trunk into the agent's own branch per the sync rules; `merge --ff-only` to update local trunk; `merge --abort`/`rebase --abort`/`cherry-pick --abort` only under W7/W13 after preserving the current state; `cherry-pick`; `revert`; `branch -d`; `tag -a` (local, in the release flow); `worktree remove` for worktrees the agent created, only after checking tracked, untracked, and ignored content per `branching-and-pr.md` §3; `bisect` only under W14 in a dedicated worktree or clean checkout | Automatic                                          |
| **Shared**     | Push the agent's own branch (`-u` the first time); open or update a PR; push new commits for review feedback                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Automatic                                          |
| **Restricted** | Destructive operations or operations that change shared refs (section 3)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Only on explicit user request, after the pre-check |
| **Forbidden**  | Section 2                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Never; hand the action to the user                 |

## 2. Forbidden

| #   | Command or behavior                                                                                                                                                                                                                                                                                                                                     | Alternative                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| F1  | Any force push: `push --force`, `-f`, `--force-with-lease`, `--force-if-includes`, `push origin +<ref>`                                                                                                                                                                                                                                                 | A new commit, or `revert`                      |
| F2  | Bulk push: `push --mirror`, `--all`, `--tags`, `--prune`                                                                                                                                                                                                                                                                                                | Push one explicit ref                          |
| F3  | Pushing directly to trunk, a protected branch, a release branch, or another person's branch                                                                                                                                                                                                                                                             | Branch + PR                                    |
| F4  | Merging into trunk by any means: local `merge` then push, the platform's merge command, enabling auto-merge, using admin rights to bypass protection                                                                                                                                                                                                    | A human merges                                 |
| F5  | Rewriting or destroying history and data: `filter-branch`, `filter-repo`, BFG, `reflog expire`, `gc --prune=now`, `git prune`, `update-ref -d`                                                                                                                                                                                                          | —                                              |
| F6  | Rewriting a commit that has been published or was authored by someone else, including using `commit --amend`, `rebase`, or `reset` to rewrite that commit                                                                                                                                                                                               | A new commit, or `revert`                      |
| F7  | Bypassing safeguards: `commit --no-verify`/`-n`, `push --no-verify`, `--no-gpg-sign`, `-c commit.gpgsign=false`, `-c core.hooksPath=...`, disabling hooks through environment variables, skipping CI checks                                                                                                                                             | Fix the cause of the hook or CI failure        |
| F8  | Writing global or system config; changing or overriding author/committer identity via `git config`, `git -c user.name=...`, `git -c user.email=...`, `--author`, or `GIT_AUTHOR_*`/`GIT_COMMITTER_*` environment variables                                                                                                                              | —                                              |
| F9  | Interactive or blocking commands: `rebase -i` (except the non-interactive autosquash of confirmed-unpublished commits under commit-convention §8), `add -i`, `add -p`, `commit` when it would open an editor (for example, without `-m`/`-F`), `merge` without `-m`/`--no-edit`, `revert` without `--no-edit` when it creates a commit, and `mergetool` | The equivalent non-interactive command         |
| F10 | Adding a `Signed-off-by` trailer or using `commit -s`/`--signoff`                                                                                                                                                                                                                                                                                       | Only a human adds it                           |
| F11 | Altering published tags: `tag -f`, `tag -d` on a pushed tag, overwriting a pushed tag, `push --delete` of a tag                                                                                                                                                                                                                                         | A new version tag                              |
| F12 | Deleting the remote trunk or a protected branch                                                                                                                                                                                                                                                                                                         | —                                              |
| F13 | Committing secrets, credentials, files containing private environment values, or private keys. Placeholder-only templates such as `.env.example` are allowed only when the project expects them and a diff review confirms they contain no secrets                                                                                                      | Do not stage the sensitive file; tell the user |
| F14 | Removing or modifying worktrees the agent did not create                                                                                                                                                                                                                                                                                                | —                                              |
| F15 | Changing hosting platform settings: branch protection, webhooks, secrets, access control                                                                                                                                                                                                                                                                | —                                              |

## 3. Restricted

If a pre-check fails, do not run the command; report it with the handoff template. For `git fetch`, use the intended remote and standard refspecs unless the task explicitly requires otherwise; fetch updates remote-tracking refs, `FETCH_HEAD`, and repository objects, even though it does not normally change the checked-out branch or working tree.

| #   | Command                                               | Required pre-check                                                                                                                                                                                                                                                                                                                                          |
| --- | ----------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | `git reset --hard`                                    | `git status` shows no unsaved changes that belong to the user; commit or stash the agent's own work first; record the current sha                                                                                                                                                                                                                           |
| R2  | `git clean -f`, `-fd`, `-fdx`, `-x`                   | Run a dry run with the same scope, pathspec, and removal options, replacing the force/removal action with `-n` (for example, `git clean -ndx -- <same-pathspec>` for `-fdx`). Show the exact output and obtain explicit user confirmation before deletion. If the command would target nested Git repositories or the scope is ambiguous, stop and hand off |
| R3  | Broad discard: `git restore .`, `git checkout -- .`   | Confirm every change was made by the agent                                                                                                                                                                                                                                                                                                                  |
| R4  | `git branch -D`                                       | The deletion conditions in `branching-and-pr.md` hold (or the user confirmed abandoning the branch); record the tip sha                                                                                                                                                                                                                                     |
| R5  | `git stash drop`, `git stash clear`                   | Inspect the stash content; only stashes the agent created                                                                                                                                                                                                                                                                                                   |
| R6  | `git push origin --delete <branch>`                   | Only the agent's own branch; the deletion conditions hold                                                                                                                                                                                                                                                                                                   |
| R7  | `git push origin <tag>`                               | One annotated tag on a commit already on trunk (or the release branch). Satisfied when the user asked for the release and confirmed the release PR is merged (`release.md` section 6), or when the user asks explicitly                                                                                                                                     |
| R8  | `git config` (local), `git remote add/set-url/remove` | Show the existing value and proposed value before changing it; identity changes and safety-bypass settings remain Forbidden under F7/F8                                                                                                                                                                                                                     |
| R9  | `git worktree remove --force`                         | Only a worktree the agent created; inspect `git -C <path> status --short --ignored`, preserve valuable local data, show the exact path and any uncommitted/untracked/ignored data that would be lost, then obtain explicit confirmation for that path                                                                                                       |
| R10 | `git worktree prune` (without `-n`)                   | The user explicitly requested cleanup. First run `git worktree prune -n -v` with the same expiration options; every stale entry must be verified as an agent-created worktree that was intentionally removed. If any entry is unknown or belongs to another worker/user, do not prune; hand off to the user                                                 |

## 4. Handling a blocked action

When an action is Forbidden, or Restricted without authorization:

1. Do not run it, and do not run a near-equivalent that has the same effect.
2. Use the handoff template in `SKILL.md` (Output).
3. Continue with whatever safe work remains.
