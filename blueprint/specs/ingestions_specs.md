# UniHub Workshop - Ingestions Specifications

This module preserves the internal batch processing lifecycle for manual ingestion triggers, scheduled CSV imports, schema validation, quarantine, and bulk upsert. It keeps the ingestion pipeline idempotent, streaming, and audit friendly while publishing progress through the event publication registry.

## 1. Trigger Manual Ingestion

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                                 |
| :---------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Trigger Manual Ingestion                                                                                                                                                                                                                                                                                                                                                                |
| **Description**         | Manually start a CSV ingestion job for a specific file stored in object storage.                                                                                                                                                                                                                                                                                                        |
| **Actors**              | Organizer                                                                                                                                                                                                                                                                                                                                                                               |
| **Main Flow**           | 1. The system validates the request payload and the object storage reference.<br>2. The system checks whether an ingestion job is already running.<br>3. The system creates a new batch record in `student_import_batches` with `PROCESSING` status.<br>4. The system starts the batch job with the target file reference.<br>5. The system returns HTTP 202 with the batch identifier. |
| **Error Scenarios**     | - A running job returns HTTP 409.<br>- An invalid storage reference returns HTTP 400.<br>- Unauthorized access returns HTTP 401.                                                                                                                                                                                                                                                        |
| **Constraints**         | - Only one ingestion job may run at a time.<br>- The `student_import_batches` table stores the batch state.                                                                                                                                                                                                                                                                             |
| **Acceptance Criteria** | - A valid request starts a batch and returns the batch identifier.<br>- Overlapping requests are rejected with HTTP 409.                                                                                                                                                                                                                                                                |

## 2. Get Batch Status and Report

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                |
| :---------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Get Batch Status and Report                                                                                                                                                                                                                                                                                                                                            |
| **Description**         | Return the batch status together with the quarantined row report for a specific ingestion run.                                                                                                                                                                                                                                                                         |
| **Actors**              | Organizer                                                                                                                                                                                                                                                                                                                                                              |
| **Main Flow**           | 1. The system validates the batch identifier and pagination parameters.<br>2. The system queries `student_import_batches` for the batch status and processed counts.<br>3. The system queries `student_import_errors` with pagination for quarantined rows and failure reasons.<br>4. The system returns the batch status, processed totals, and the paged error list. |
| **Error Scenarios**     | - A missing batch returns HTTP 404.<br>- Unauthorized access returns HTTP 401.                                                                                                                                                                                                                                                                                         |
| **Constraints**         | - Status values are limited to `PROCESSING`, `COMPLETED`, and `FAILED`.<br>- Pagination is mandatory for the error list.<br>- The report is read only and immutable.                                                                                                                                                                                                   |
| **Acceptance Criteria** | - Status and counts match the persisted batch records.<br>- Quarantined rows are returned as a deterministically paged list.                                                                                                                                                                                                                                           |

## 3. Nightly Scheduled Cronjob Trigger

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| :---------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Nightly Scheduled Cronjob Trigger                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Description**         | Start a nightly ingestion run to pick up new CSV drops.                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Actors**              | Internal System                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Main Flow**           | 1. The system starts the ingestion workflow at the configured off peak time.<br>2. The system checks for new CSV drops in the storage bucket.<br>3. The system checks whether another ingestion job is already running in `student_import_batches`.<br>4. The system aborts the cron trigger when a job is already running to prevent collision.<br>5. The system enqueues the batch job and records a new `PROCESSING` batch row when a file is available. |
| **Error Scenarios**     | - Storage unavailable returns HTTP 503.<br>- Scheduler failure returns HTTP 500.                                                                                                                                                                                                                                                                                                                                                                            |
| **Constraints**         | - The scheduler must run at a fixed off peak time.<br>- Only one scheduled job may execute per window.<br>- The `student_import_batches` table tracks the running job.                                                                                                                                                                                                                                                                                      |
| **Acceptance Criteria** | - New CSV drops trigger an ingestion job.<br>- Duplicate batch rows are not created for the same schedule window.                                                                                                                                                                                                                                                                                                                                           |

## 4. CSV File Fetch and Validation

| Field                   | Details                                                                                                                                                                                                                                                                              |
| :---------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | CSV File Fetch and Validation                                                                                                                                                                                                                                                        |
| **Description**         | Fetch the CSV file and validate its structure before row processing begins.                                                                                                                                                                                                          |
| **Actors**              | Internal System                                                                                                                                                                                                                                                                      |
| **Main Flow**           | 1. The system downloads the target CSV file from object storage.<br>2. The system validates the MIME type and file size limits.<br>3. The system validates the required headers and schema.<br>4. The system marks the batch as `FAILED` and stops processing when validation fails. |
| **Error Scenarios**     | - A missing file returns a failed batch state.<br>- Invalid headers or schema return a failed batch state.<br>- A file that is too large returns a failed batch state.                                                                                                               |
| **Constraints**         | - File level validation must complete before any row processing begins.<br>- Invalid files must abort the job safely.                                                                                                                                                                |
| **Acceptance Criteria** | - Valid files proceed to chunk processing.<br>- Invalid files are rejected and marked `FAILED`.                                                                                                                                                                                      |

## 5. Chunk Processing and Bulk Upsert

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                                  |
| :---------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Chunk Processing and Bulk Upsert                                                                                                                                                                                                                                                                                                                                                         |
| **Description**         | Process the CSV in chunks and upsert student records into the database.                                                                                                                                                                                                                                                                                                                  |
| **Actors**              | Internal System                                                                                                                                                                                                                                                                                                                                                                          |
| **Main Flow**           | 1. The system reads the CSV in fixed size chunks.<br>2. The system deduplicates rows in memory within each chunk.<br>3. The system validates row level fields such as email format and required columns.<br>4. The system bulk upserts the rows into the `users` table within a per chunk transaction.<br>5. The system commits the chunk transaction and continues with the next chunk. |
| **Error Scenarios**     | - A database failure returns a failed batch state.<br>- A chunk write failure triggers retry or abort according to policy.                                                                                                                                                                                                                                                               |
| **Constraints**         | - Transaction boundaries must be per chunk to avoid memory exhaustion and connection exhaustion.<br>- Upserts must be idempotent for repeated rows.<br>- The `users` table is the target write table.                                                                                                                                                                                    |
| **Acceptance Criteria** | - Valid rows are inserted or updated correctly.<br>- Chunk processing continues across large files without exhausting resources.                                                                                                                                                                                                                                                         |

## 6. Error Quarantining and Archiving

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                              |
| :---------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Error Quarantining and Archiving                                                                                                                                                                                                                                                                                                                                                     |
| **Description**         | Isolate invalid rows and archive the source CSV after completion.                                                                                                                                                                                                                                                                                                                    |
| **Actors**              | Internal System                                                                                                                                                                                                                                                                                                                                                                      |
| **Main Flow**           | 1. The system skips rows that fail validation and captures the error details.<br>2. The system inserts the raw row data and the error reason into `student_import_errors`.<br>3. The system continues processing the remaining rows in the chunk.<br>4. The system archives the source CSV after the job completes and publishes a `CsvIngestionCompleted` event with batch metrics. |
| **Error Scenarios**     | - An error table insert failure returns HTTP 500.<br>- An archive move failure returns HTTP 500.                                                                                                                                                                                                                                                                                     |
| **Constraints**         | - Skip policy must allow processing to continue after bad rows.<br>- The source CSV must be archived to prevent reprocessing.<br>- The `student_import_errors` table stores quarantined rows.                                                                                                                                                                                        |
| **Acceptance Criteria** | - Invalid rows are quarantined with reasons.<br>- Processing completes, the source file is archived, and the event is published.                                                                                                                                                                                                                                                     |
