# UniHub Workshop - Workshop Management Specs

## 1. Get Workshop List

Defines organizer-only access to workshop listings with ownership rules and query controls.

| Field               | Details                                                                                                                                                                                                                                                                                              |
| :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Get Workshop List                                                                                                                                                                                                                                                                                    |
| Description         | Retrieves a filtered, sortable, paginated list of workshops for the current organizer.                                                                                                                                                                                                               |
| Main Flow           | 1. Validate pagination, sorting, and filter parameters.<br>2. Resolve organizer identity from the Security Context.<br>3. Hard-scope the query to `organizer_id` from the Security Context.<br>4. Apply status and date-range filters if provided.<br>5. Return paginated list with sorting applied. |
| Error Scenarios     | - Invalid pagination or sort field returns 400.<br>- Unauthorized access returns 401.<br>- Non-organizer role returns 403.                                                                                                                                                                           |
| Constraints         | - Organizers can only list their own workshops.<br>- Sorting and filters must be indexed fields to avoid full scans.<br>- No cross-organizer access is allowed.                                                                                                                                      |
| Acceptance Criteria | - Organizer sees only owned workshops.<br>- Pagination and sorting behave deterministically.<br>- Cross-organizer access is never returned.                                                                                                                                                          |

## 3. Create Workshop Draft

Defines draft creation and initial validation rules.

| Field               | Details                                                                                                                                                                                                                                                                                                                                                                                           |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Use Case Name       | Create Workshop Draft                                                                                                                                                                                                                                                                                                                                                                             |
| Description         | Creates a new workshop in the DRAFT state with validated time boundaries.                                                                                                                                                                                                                                                                                                                         |
| Main Flow           | 1. Validate input fields and organizer identity.<br>2. Ensure `start_time` is in the future.<br>3. Ensure `end_time` is strictly after `start_time`.<br>4. Create workshop with status `DRAFT` and organizer ownership.<br>5. Initialize optimistic lock `version` (for example, 0 or 1); if `capacity_total` is provided, set `capacity_remaining` to match.<br>6. Return created draft details. |
| Error Scenarios     | - Invalid time range returns 400.<br>- Start time in the past returns 400.<br>- Unauthorized access returns 401.                                                                                                                                                                                                                                                                                  |
| Constraints         | - Status must be `DRAFT` on creation.<br>- `end_time` must be strictly after `start_time`.                                                                                                                                                                                                                                                                                                        |
| Acceptance Criteria | - Draft is created with `DRAFT` status.<br>- Time validation rejects invalid ranges.                                                                                                                                                                                                                                                                                                              |

## 4. Update Workshop

Defines allowed updates based on workshop state with strict ownership rules.

| Field               | Details                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| :------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Update Workshop                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Description         | Updates workshop fields based on current status with ownership enforcement.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Main Flow           | 1. Validate workshop ID and input payload.<br>2. Resolve organizer identity from the Security Context.<br>3. Enforce ownership by matching `organizer_id`; mismatch returns 403.<br>4. If status is `PUBLISHED`, block critical field changes and require Reschedule flow.<br>5. If status is `DRAFT`, allow full updates.<br>6. Validate optimistic lock: provided `version` must match stored `version`; mismatch returns 409.<br>7. If status is `DRAFT` and `capacity_total` is updated, sync `capacity_remaining` to the new `capacity_total`.<br>8. Persist changes and return updated workshop. |
| Error Scenarios     | - Workshop not found returns 404.<br>- Ownership violation returns 403.<br>- Attempt to modify restricted fields when `PUBLISHED` returns 409.<br>- Optimistic lock `version` mismatch returns 409 (concurrent edit detected).                                                                                                                                                                                                                                                                                                                                                                         |
| Constraints         | - `PUBLISHED` workshops cannot change time/location via this flow.<br>- `DRAFT` workshops allow full edits.<br>- Ownership enforcement applies to all updates with no bypass.                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Acceptance Criteria | - `DRAFT` updates succeed for owners.<br>- Restricted updates on `PUBLISHED` return 409.<br>- Non-owners are blocked with 403.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## 5. Publish Workshop

Defines the state transition from draft to published with mandatory field validation.

| Field               | Details                                                                                                                                                                                                                                                                                                                                                                 |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Publish Workshop                                                                                                                                                                                                                                                                                                                                                        |
| Description         | Transitions a workshop from `DRAFT` to `PUBLISHED` when required fields are complete.                                                                                                                                                                                                                                                                                   |
| Main Flow           | 1. Validate workshop ID and resolve organizer identity.<br>2. Enforce ownership by matching `organizer_id`; mismatch returns 403.<br>3. Verify required fields are populated (location, capacity > 0, speaker info).<br>4. Verify `start_time` is strictly in the future at publish time.<br>5. Transition status to `PUBLISHED`.<br>6. Return updated workshop status. |
| Error Scenarios     | - Missing required fields returns 400.<br>- Start time in the past at publish time returns 400.<br>- Ownership violation returns 403.<br>- Workshop not found returns 404.                                                                                                                                                                                              |
| Constraints         | - Only `DRAFT` can be published.<br>- Capacity must be greater than 0.<br>- Speaker info and location are mandatory.<br>- `start_time` must be strictly in the future at publish time.<br>- Non-owners are blocked with 403.                                                                                                                                            |
| Acceptance Criteria | - Valid draft transitions to `PUBLISHED` for the owner.<br>- Incomplete drafts are rejected with 400.<br>- Non-owners are blocked with 403.                                                                                                                                                                                                                             |

## 6. Reschedule or Relocate Workshop

Defines controlled rescheduling for published workshops with attendee notification events.

| Field               | Details                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Reschedule or Relocate Workshop                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Description         | Updates time/location for `PUBLISHED` workshops and emits attendee notifications via outbox.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Main Flow           | 1. Validate workshop ID and input payload.<br>2. Resolve organizer identity from the Security Context.<br>3. Enforce ownership by matching `organizer_id`; mismatch returns 403.<br>4. Verify workshop status is `PUBLISHED`.<br>5. Validate `start_time` is in the future and `end_time` is strictly after `start_time`.<br>6. Validate optimistic lock: provided `version` must match stored `version`; mismatch returns 409.<br>7. Update schedule or location in a transaction.<br>8. Write outbox event for attendee notifications in the same transaction.<br>9. Return updated workshop. |
| Error Scenarios     | - Workshop not found returns 404.<br>- Ownership violation returns 403.<br>- Status not `PUBLISHED` returns 409.<br>- Invalid time range returns 400.<br>- Optimistic lock `version` mismatch returns 409 (concurrent edit detected).                                                                                                                                                                                                                                                                                                                                                           |

| Acceptance Criteria | - `PUBLISHED` workshops can be rescheduled and notify attendees.<br>- Non-`PUBLISHED` workshops are rejected.<br>- Non-owners are blocked with 403.                                                                                                                                                                                                                                                                                                                                                                                                                                             |

## 7. Cancel Workshop

Defines cancellation behavior with attendee notification and audit-safe state change.

| Field               | Details                                                                                                                                                                                                                                                                                                                                        |
| :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Cancel Workshop                                                                                                                                                                                                                                                                                                                                |
| Description         | Cancels a workshop and notifies attendees via outbox events.                                                                                                                                                                                                                                                                                   |
| Main Flow           | 1. Validate workshop ID and resolve organizer identity.<br>2. Enforce ownership by matching `organizer_id`; mismatch returns 403.<br>3. | Constraints         | - Only `PUBLISHED` workshops can be canceled.<br>- `DRAFT` workshops must use Delete Workshop instead.<br>- Cancellation must preserve audit history.<br>- Outbox notification must be persisted with the cancellation.<br>- Non-owners are blocked with 403.                                                                                  |
| Acceptance Criteria | - Status is updated to `CANCELED`.<br>- Attendee notification event is emitted.<br>- Non-owners are blocked with 403.                                                                                                                                                                                                                          |

## 9. Upload Brochure PDF

Defines secure brochure upload with strict file validation.

| Field               | Details                                                                                                                                                                                                                                                                                                                                                                                                                      |
| :------------------ | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Upload Brochure PDF                                                                                                                                                                                                                                                                                                                                                                                                          |

| Acceptance Criteria | - Valid PDF uploads return 202 Accepted with a URL/key.<br>- AI summarization outbox event is emitted with the upload transaction.<br>- Invalid MIME or size is rejected.<br>- Non-owners are blocked with 403.                                                                                                                                                                                                              |
