# UniHub Workshop - Check-in & Attendance Specs

## 1. Get Assigned Workshops

Defines staff access to upcoming workshops assigned to their organization.

| Field               | Details                                                                                                                                                                                                                                       |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Get Assigned Workshops                                                                                                                                                                                                                        |
| Description         | Returns workshops assigned to the staff member for today and upcoming sessions.                                                                                                                                                               |
| Actors              | Staff                                                                                                                                                                                                                                         |
| Main Flow           | 1. Resolve staff identity and organization from Security Context.<br>2. Query workshops assigned to the organization for today and near-future dates.<br>3. Sort by start time ascending.<br>4. Return the workshop list for event selection. |
| Error Scenarios     | - Unauthorized access returns 401.<br>- Organization not found returns 404.                                                                                                                                                                   |
| Constraints         | - Results are scoped to the staff member's organization.<br>- Only today and near-future workshops are included.                                                                                                                              |
| Acceptance Criteria | - Staff sees only assigned workshops.<br>- Ordering is deterministic by start time.                                                                                                                                                           |

## 2. Download Attendee Roster

Defines bulk roster retrieval for offline-first check-in.

| Field               | Details                                                                                                                                                                                                                                                                                                           |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Download Attendee Roster                                                                                                                                                                                                                                                                                          |
| Description         | Fetches the list of eligible attendees for offline caching.                                                                                                                                                                                                                                                       |
| Actors              | Staff                                                                                                                                                                                                                                                                                                             |
| Main Flow           | 1. Validate workshop ID format.<br>2. Resolve staff identity and organization from Security Context.<br>3. Enforce access to assigned workshop only; mismatch returns 403.<br>4. Query registrations with status `CONFIRMED` or `PAID`.<br>5. Return roster as paginated or bulk sync response for local caching. |
| Error Scenarios     | - Workshop not found returns 404.<br>- Ownership violation returns 403.<br>- Unauthorized access returns 401.                                                                                                                                                                                                     |
| Constraints         | - Only `CONFIRMED` or `PAID` registrations are included.<br>- Response must support pagination or bulk sync for mobile caching.                                                                                                                                                                                   |
| Acceptance Criteria | - Mobile app can cache roster locally for offline search.<br>- Non-assigned staff cannot access the roster.                                                                                                                                                                                                       |

## 3. Sync Check-in Batch

Defines offline batch synchronization for check-in events.

| Field               | Details                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Sync Check-in Batch                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Description         | Processes an array of offline check-in events and returns per-record outcomes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Actors              | Staff                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Main Flow           | 1. Validate batch payload and workshop ID references.<br>2. Resolve staff identity and organization from Security Context.<br>3. For each check-in event, verify QR signature (Table 6) and ensure the QR `workshop_id` strictly matches the target `workshop_id`; mismatches are rejected (poison pill).<br>4. Apply conflict resolution and poison pill handling (Table 5).<br>5. Persist each successful check-in with `scanned_at` and `offline_mode_flag` in its own isolated transaction.<br>6. Return a response with `success`, `duplicates`, and `rejected` identifiers. |
| Error Scenarios     | - Unauthorized access returns 401.<br>- Invalid payload returns 400.<br>- Workshop not assigned returns 403.                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Constraints         | - Batch processing must be idempotent per event.<br>- Database transactions must be scoped per-record, not per-batch, to allow partial success and prevent one bad row from failing the entire array.<br>- Response must categorize records into `success`, `duplicates`, and `rejected` to prevent infinite retries.                                                                                                                                                                                                                                                             |
| Acceptance Criteria | - Successful scans are recorded once.<br>- Duplicates are acknowledged without errors.<br>- Poison pill records are rejected and not retried.                                                                                                                                                                                                                                                                                                                                                                                                                                     |

Defines staff access to live attendance metrics.

| :------------------ | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Get Real-time Stats                                                                                                                                                                                                                                                      |
| Description         | Returns live capacity, registered, and checked-in counts for a workshop.                                                                                                                                                                                                 |
| Actors              | Staff                                                                                                                                                                                                                                                                    |
| Main Flow           | 1. Validate workshop ID format.<br>2. Resolve staff identity and organization from Security Context.<br>3. Enforce access to assigned workshop only; mismatch returns 403.<br>4. Query live counts (capacity, registered, checked-in).<br>5. Return the metrics payload. |
| Error Scenarios     | - Workshop not found returns 404.<br>- Ownership violation returns 403.<br>- Unauthorized access returns 401.                                                                                                                                                            |
| Constraints         | - Metrics must be derived from authoritative transactional data.<br>- Access is limited to assigned workshops.                                                                                                                                                           |
| Acceptance Criteria | - Returned metrics match current database values.<br>- Non-assigned staff cannot access stats.                                                                                                                                                                           |

## 5. Conflict Resolution & Poison Pill Handling

Defines idempotent handling for duplicates and invalid records.

| Field               | Details                                                                                                                                                                                                                                                                                                                                         |
| :------------------ | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | Conflict Resolution & Poison Pill Handling                                                                                                                                                                                                                                                                                                      |
| Description         | Classifies duplicates and invalid records to prevent retry storms.                                                                                                                                                                                                                                                                              |
| Actors              | Internal System                                                                                                                                                                                                                                                                                                                                 |
| Main Flow           | 1. Load registration by `registration_id` from the decoded QR payload.<br>2. If status is `CHECKED_IN`, return as idempotent duplicate.<br>3. If status is `CANCELED` or `FAILED`, mark as rejected (poison pill).<br>4. If registration is missing, mark as rejected (poison pill).<br>5. If status is eligible, allow processing to continue. |
| Error Scenarios     | - Database unavailable returns 503 (internal error).                                                                                                                                                                                                                                                                                            |
| Constraints         | - Duplicate check-ins must not raise errors to avoid retry loops.<br>- Poison pill records must be explicitly rejected so the client stops retrying.                                                                                                                                                                                            |
| Acceptance Criteria | - Duplicates are reported as `duplicates` without mutation.<br>- Invalid registrations are classified as `rejected`.                                                                                                                                                                                                                            |

## 6. QR Signature Verification

Defines cryptographic validation of scanned QR payloads.

| Field               | Details                                                                                                                                                                                                                                                                                     |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Use Case Name       | QR Signature Verification                                                                                                                                                                                                                                                                   |
| Description         | Verifies QR payload integrity and extracts the registration reference.                                                                                                                                                                                                                      |
| Actors              | Internal System                                                                                                                                                                                                                                                                             |
| Main Flow           | 1. Decode the QR JWT payload.<br>2. Verify signature using the system key.<br>3. Validate payload claims (issuer, expiry, workshop_id).<br>4. Extract `registration_id` and forward to conflict resolution (Table 5).<br>5. If validation fails, mark the record as rejected (poison pill). |
| Error Scenarios     | - Invalid signature or tampered payload returns rejected (poison pill).<br>- Expired token returns rejected (poison pill).                                                                                                                                                                  |
| Constraints         | - Verification must be deterministic and side-effect free.<br>- Invalid payloads must never update attendance state.                                                                                                                                                                        |
| Acceptance Criteria | - Valid QR payloads proceed to conflict resolution.<br>- Invalid payloads are rejected and not retried.                                                                                                                                                                                     |
