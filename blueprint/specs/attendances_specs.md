# UniHub Workshop - Attendances Specifications

This module owns staff-facing attendance operations, QR-based check-in processing, offline reconciliation, and reporting for assigned workshops. It enforces deterministic and tenant-scoped updates so that attendance records and registration states remain consistent under concurrent and offline workflows.

## 1. Get Assigned Workshops

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                             |
| :---------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Get Assigned Workshops                                                                                                                                                                                                                                                                                                                                                              |
| **Description**         | Return the workshops assigned to a staff member (by `staff_id`) for current and upcoming sessions.                                                                                                                                                                                                                                                                                  |
| **Actors**              | Staff                                                                                                                                                                                                                                                                                                                                                                               |
| **Main Flow**           | 1. The system resolves the staff identity from the security context.<br>2. The system queries `workshop_assignments` filtering where `staff_id` = authenticated staff's id and joins to `workshops` for current and upcoming dates.<br>3. The system sorts results by start time in ascending order.<br>4. The system returns the workshop list for operational check-in selection. |
| **Error Scenarios**     | - The system returns HTTP 401 when the caller is not authenticated.<br>- The system returns HTTP 404 when the staff organization cannot be resolved.                                                                                                                                                                                                                                |
| **Constraints**         | - Results must be scoped to the authenticated staff member by `staff_id`.<br>- Only current and near-future workshops are included.<br>- The `workshop_assignments` (using `staff_id`) and `workshops` tables define assignment scope and schedule.                                                                                                                                 |
| **Acceptance Criteria** | - Staff users see only assigned workshops.<br>- Ordering remains deterministic by start time.                                                                                                                                                                                                                                                                                       |

## 2. Download Attendee Roster

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| :---------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Download Attendee Roster                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Description**         | Fetch the eligible attendee roster for online and offline check-in workflows.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Actors**              | Staff                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Main Flow**           | 1. The system validates the workshop identifier.<br>2. The system resolves staff identity and organization from the security context.<br>3. The system verifies that the workshop is assigned to the staff organization.<br>4. The system queries registration rows eligible for check-in workflows.<br>5. The system returns the roster as either a paged response or a bulk sync payload.<br>6. The payload MUST include the System Public Key (RSA public key material) or a reference to it so the mobile client can cryptographically verify QR JWT signatures while fully offline. |
| **Error Scenarios**     | - The system returns HTTP 404 when the workshop is missing.<br>- The system returns HTTP 403 when assignment or ownership validation fails.<br>- The system returns HTTP 401 when the caller is not authenticated.                                                                                                                                                                                                                                                                                                                                                                       |
| **Constraints**         | - Only `CONFIRMED` registrations are included.<br>- The response must support pagination or bulk payload delivery for offline clients.<br>- The `registrations` table is the roster source and must remain tenant-scoped.<br>- The roster payload MUST include or reference the System RSA Public Key so authorized staff clients can verify QR JWT signatures offline. Mobile clients SHOULD cache the public key and refresh it periodically.                                                                                                                                          |
| **Acceptance Criteria** | - Staff clients can cache a valid attendee roster for assigned workshops.<br>- Non-assigned staff cannot access roster data.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

## 3. Process QR Check-in

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| :---------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Process QR Check-in                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Description**         | Decode, validate, and atomically process QR check-ins while preventing duplicate scans and invalid status transitions.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Actors**              | Staff, Internal System                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Main Flow**           | 1. The system decodes the QR JWT payload and verifies the JWT signature using the System RSA Public Key.<br>2. The system validates workshop and session identifiers from token claims and confirms claim integrity and expiration.<br>3. The system queries the `registrations` table for the referenced registration and confirms the student is in `CONFIRMED` status.<br>4. The system verifies that the token JTI has not been used by checking a Redis blocklist and authoritative attendances state in the `attendances` table.<br>5. The system starts a database transaction for check-in mutation.<br>6. The system inserts an attendances row into the `attendances` table. The insertion MUST NOT rely on changing the `registrations` table to record check-in state - the presence of an attendance row is the canonical evidence of a check-in.<br>7. The system commits the transaction, records JTI replay protection metadata in Redis, and returns a successful check-in response. |
| **Error Scenarios**     | - The system returns HTTP 401 when JWT signature verification fails or the token is expired.<br>- The system returns HTTP 409 when the registration is not in `CONFIRMED` status.<br>- The system returns HTTP 409 when the JTI was already processed and indicates a duplicate scan.<br>- The system returns HTTP 404 when the registration or workshop reference cannot be found.<br>- The system returns HTTP 503 when transactional persistence fails.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Constraints**         | - Registrations MUST be in `CONFIRMED` status to be eligible for check-in validation.<br>- The system must use a database transaction so the attendances insertion and any auxiliary writes (e.g., JTI blocklist) succeed or fail together.<br>- JTI replay prevention must be enforced using Redis and authoritative checks against `attendances` and `registrations` data.<br>- The `attendances` uniqueness by registration must be respected to prevent duplicate check-ins.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Acceptance Criteria** | - A valid QR code produces exactly one attendance record.<br>- Duplicate scans do not create additional attendance rows.<br>- Invalid or tampered tokens are rejected without mutating data.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

## 4. Offline Batch Syncing

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| :---------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Offline Batch Syncing                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Description**         | Reconcile offline scan batches into authoritative attendance and registration state records.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Actors**              | Staff, Internal System                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Main Flow**           | 1. The system accepts a signed batch payload with scanner metadata and submission context.<br>2. The system validates payload signature, schema, and workshop references.<br>3. The system validates each scan record, deduplicates by QR JTI, and processes records in transactional chunks.<br>4. For every successfully reconciled attendance row the system persists the `attendances` row; the system MUST NOT update `registrations.status` to record check-in - attendance rows are canonical evidence of check-in.<br>5. If an individual scan record violates the unique constraint on `attendances.registration_id` (indicating the QR was already scanned and synced), the backend MUST mark that specific record as `Ignored/Duplicate` in the reconciliation outcome and CONTINUE processing the remainder of the batch. The backend MUST NOT fail the entire batch with an HTTP 500 for such duplicates.<br>6. The system persists reconciliation outcomes and publishes a batch synchronized event with success and failure counts. |
| **Error Scenarios**     | - The system returns HTTP 401 when batch signature validation fails.<br>- The system returns HTTP 400 when schema validation fails.<br>- The system returns HTTP 207 when partial reconciliation succeeds with per-record failures.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Constraints**         | - The JTI from each QR payload must be enforced as a unique deduplication key across sync retries.<br>- Batch processing must preserve atomicity per chunk for `attendances` inserts and any auxiliary writes (e.g., JTI blocklist).<br>- Attendance insertions are canonical evidence of check-in; the system MUST NOT rely on a separate registration status to record check-in - the presence of an `attendances` row is authoritative.<br>- Timestamp fields must use `TIMESTAMPTZ` semantics for consistent audit chronology.<br>- The batch sync endpoint MUST implement partial-success semantics: validation failures for individual JTIs (for example, a registration cancelled while the staff was offline - a "poison pill") MUST NOT abort processing of the remaining batch.<br>- The batch response MUST include per-JTI result entries that indicate success or failure and a concise failure reason so the mobile client can clear or retry specific JTIs.                                                                         |
| **Acceptance Criteria** | - Valid offline scans are reconciled without duplicate attendance records.<br>- Attendance rows are authoritative proof of check-in; registration rows are not required to be mutated to reflect check-in.<br>- Partial failures are reported with precise reconciliation details.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

## 5. Get Real-time Stats

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                                       |
| :---------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Get Real-time Stats                                                                                                                                                                                                                                                                                                                                                                           |
| **Description**         | Return live attendance and capacity metrics for an assigned workshop.                                                                                                                                                                                                                                                                                                                         |
| **Actors**              | Staff                                                                                                                                                                                                                                                                                                                                                                                         |
| **Main Flow**           | 1. The system validates the workshop identifier.<br>2. The system resolves staff identity and organization from the security context.<br>3. The system verifies assignment access for the requested workshop.<br>4. The system aggregates live metrics for capacity, registered attendees, and checked-in attendees.<br>5. The system returns the metrics payload for operational monitoring. |
| **Error Scenarios**     | - The system returns HTTP 404 when the workshop is missing.<br>- The system returns HTTP 403 when assignment validation fails.<br>- The system returns HTTP 401 when the caller is not authenticated.                                                                                                                                                                                         |
| **Constraints**         | - Metrics must be sourced from authoritative transactional records.<br>- Access must remain limited to assigned workshops only.<br>- The `workshops`, `registrations`, and `attendances` tables provide the live metric inputs.                                                                                                                                                               |
| **Acceptance Criteria** | - Returned metrics match current persisted values.<br>- Non-assigned staff cannot access workshop metrics.                                                                                                                                                                                                                                                                                    |
