# UniHub Workshop - AI Summarization Specifications

This module preserves the internal worker lifecycle for brochure text extraction, AI summarization, publication, and retry handling. It is intentionally internal only and keeps all processing stages event driven through published events and resilient retry flows.

## 1. Get AI Summary Status and Result

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| :---------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | Get AI Summary Status and Result                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Description**         | Return the AI summary status and final result for a workshop.                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Actors**              | Organizer                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Main Flow**           | 1. The system validates the workshop identifier.<br>2. The system resolves the organizer identity from the security context.<br>3. The system verifies that the workshop is owned by the organizer.<br>4. The system queries the `ai_summaries` table for the workshop.<br>5. The system returns status only when processing is still running.<br>6. The system returns the summary text and status when processing is completed.<br>7. The system returns the failure status and error details when processing has failed. |
| **Error Scenarios**     | - A missing workshop returns HTTP 404.<br>- Ownership violations return HTTP 403.<br>- A missing summary record returns HTTP 404.                                                                                                                                                                                                                                                                                                                                                                                           |
| **Constraints**         | - Access is limited to the workshop owner.<br>- The `ai_summaries` table must reflect the latest AI job state.                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Acceptance Criteria** | - Processing returns a status for polling.<br>- Completed work returns the final summary text.<br>- Failed work returns the error state.                                                                                                                                                                                                                                                                                                                                                                                    |

## 2. AI Summarization Event Publication

| Field                   | Details                                                                                                                                                                                                                                   |
| :---------------------- | :---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | AI Summarization Event Publication                                                                                                                                                                                                        |
| **Description**         | Externalize AI summarization jobs through the Spring Modulith event publication registry.                                                                                                                                                 |
| **Actors**              | Internal System                                                                                                                                                                                                                           |
| **Main Flow**           | 1. The system persists the AI publication record in the originating transaction.<br>2. The system externalizes the pending publication to RabbitMQ.<br>3. The system marks the publication as completed after successful externalization. |
| **Error Scenarios**     | - RabbitMQ unavailable returns a retryable failure.<br>- Database unavailable returns HTTP 503.                                                                                                                                           |
| **Constraints**         | - Each event publication must be externalized at least once.<br>- Publication state transitions must remain transactional.<br>- The event publication registry is the source of truth for pending jobs.                                   |
| **Acceptance Criteria** | - AI jobs are published to RabbitMQ.<br>- Event publication entries are marked completed.                                                                                                                                                 |

## 3. AI Summarization Worker

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| :---------------------- | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | AI Summarization Worker                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Description**         | Consume AI jobs, generate summaries, and persist the results.                                                                                                                                                                                                                                                                                                                                                                           |
| **Actors**              | Internal System                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Main Flow**           | 1. The system consumes the job message from RabbitMQ.<br>2. The system fetches the brochure from object storage.<br>3. The system extracts the text locally using the appropriate parser.<br>4. The system cleans and chunks the text to satisfy token limits.<br>5. The system calls the external AI service with the prepared chunks.<br>6. The system persists the summary text in the `ai_summaries` table with `COMPLETED` status. |
| **Error Scenarios**     | - A missing brochure returns a failed state.<br>- An AI service timeout or server failure returns a retryable failure.<br>- A storage failure returns a retryable failure.                                                                                                                                                                                                                                                              |
| **Constraints**         | - Summaries must come from the latest uploaded brochure.<br>- The persisted summary must remain linked to the workshop.<br>- The `ai_summaries` table stores the output.                                                                                                                                                                                                                                                                |
| **Acceptance Criteria** | - Successful jobs store summary text with `COMPLETED` status.<br>- Failed jobs are routed to retry handling.                                                                                                                                                                                                                                                                                                                            |

## 4. AI Fault Tolerance and Dead Letter Queue

| Field                   | Details                                                                                                                                                                                                                                                                                                                                                                |
| :---------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Use Case Name**       | AI Fault Tolerance and Dead Letter Queue                                                                                                                                                                                                                                                                                                                               |
| **Description**         | Retry failed AI jobs and route exhausted retries to the dead letter queue.                                                                                                                                                                                                                                                                                             |
| **Actors**              | Internal System                                                                                                                                                                                                                                                                                                                                                        |
| **Main Flow**           | 1. The system detects transient AI failures such as timeouts or server failures.<br>2. The system requeues the job with exponential backoff and increments the retry count.<br>3. The system routes the job to the dead letter queue after the maximum retry threshold is exceeded.<br>4. The system updates the `ai_summaries` table to `FAILED` with error metadata. |
| **Error Scenarios**     | - Retry enqueue failures return HTTP 500.<br>- Dead letter queue failures return HTTP 500.                                                                                                                                                                                                                                                                             |
| **Constraints**         | - Exponential backoff is required for retries.<br>- Dead letter routing occurs after the maximum retry threshold is exceeded.<br>- Retry metadata must remain idempotent per job identifier.                                                                                                                                                                           |
| **Acceptance Criteria** | - Transient failures are retried with backoff.<br>- Exhausted retries end in the dead letter queue with `FAILED` status.                                                                                                                                                                                                                                               |
