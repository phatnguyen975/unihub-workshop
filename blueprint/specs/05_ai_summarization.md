# UniHub Workshop - AI Summarization Specs

## 1. Get AI Summary Status & Result

Defines organizer polling for AI summary job status and output.

| Field               | Details                                                                                                                                                                                                                                                                                                                                                                                           |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Use Case Name       | Get AI Summary Status & Result                                                                                                                                                                                                                                                                                                                                                                    |
| Description         | Returns the AI summarization status and final result for a workshop.                                                                                                                                                                                                                                                                                                                              |
| Actors              | Organizer                                                                                                                                                                                                                                                                                                                                                                                         |
| Main Flow           | 1. Validate workshop ID format.<br>2. Resolve organizer identity from Security Context.<br>3. Enforce ownership by matching `organizer_id`; mismatch returns 403.<br>4. Query `AI_SUMMARIES` for the workshop.<br>5. If status is `PROCESSING`, return status only.<br>6. If status is `COMPLETED`, return summary text and status.<br>7. If status is `FAILED`, return status and error details. |
| Error Scenarios     | - Workshop not found returns 404.<br>- Ownership violation returns 403.<br>- Summary record not found returns 404.                                                                                                                                                                                                                                                                                |
| Constraints         | - Access is limited to the workshop owner.<br>- Status must reflect the latest AI job state.                                                                                                                                                                                                                                                                                                      |
| Acceptance Criteria | - `PROCESSING` returns a status for polling.<br>- `COMPLETED` returns the final summary text.<br>- `FAILED` returns the error state.                                                                                                                                                                                                                                                              |

## 2. AI Summarization Event Publication

Defines the Spring Modulith Event Publication registry that externalizes AI jobs to RabbitMQ.

| Field               | Details                                                                                                                                                                                                                     |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | AI Summarization Event Publication                                                                                                                                                                                          |
| Description         | Externalizes AI summarization event publications to RabbitMQ.                                                                                                                                                               |
| Actors              | Internal System                                                                                                                                                                                                             |
| Main Flow           | 1. Persist the AI summarization event publication in the originating transaction.<br>2. Spring Modulith externalizes the pending publication to RabbitMQ.<br>3. The registry marks the publication as completed on success. |
| Error Scenarios     | - RabbitMQ unavailable returns retryable failure.<br>- Database unavailable returns 503 (internal error).                                                                                                                   |
| Constraints         | - Each event publication must be externalized at least once.<br>- Publication state transitions must be transactional.                                                                                                      |
| Acceptance Criteria | - AI jobs are published to RabbitMQ.<br>- Event publication entries are marked completed.                                                                                                                                   |

## 3. AI Summarization Worker

Defines the worker that retrieves PDFs, calls AI services, and stores summaries.

| Field               | Details                                                                                                                                                                                                                                                                                                             |
| :------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Use Case Name       | AI Summarization Worker                                                                                                                                                                                                                                                                                             |
| Description         | Consumes AI jobs, generates summaries, and persists results.                                                                                                                                                                                                                                                        |
| Actors              | Internal System                                                                                                                                                                                                                                                                                                     |
| Main Flow           | 1. Consume job message from RabbitMQ.<br>2. Fetch PDF from S3-compatible storage.<br>3. Extract text locally (for example, PDFBox).<br>4. Clean and chunk text to meet token limits.<br>5. Call external AI service with the prepared chunks.<br>6. Persist summary text in `AI_SUMMARIES` with status `COMPLETED`. |
| Error Scenarios     | - PDF missing returns failed state.<br>- AI service timeout or 5xx returns retryable failure.<br>- Storage unavailable returns retryable failure.                                                                                                                                                                   |
| Constraints         | - Summaries must be derived from the latest uploaded brochure.<br>- Persisted summary must be linked to the workshop.                                                                                                                                                                                               |
| Acceptance Criteria | - Successful jobs store summary text with `COMPLETED` status.<br>- Failed jobs are routed to retry handling.                                                                                                                                                                                                        |

## 4. AI Fault Tolerance & Dead Letter Queue

Defines retry behavior and DLQ handling for failed AI jobs.

| Field               | Details                                                                                                                                                                                                                                                   |
| :------------------ | :-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use Case Name       | AI Fault Tolerance & Dead Letter Queue                                                                                                                                                                                                                    |
| Description         | Retries failed AI jobs and routes exhausted retries to a DLQ.                                                                                                                                                                                             |
| Actors              | Internal System                                                                                                                                                                                                                                           |
| Main Flow           | 1. Detect transient AI failures (timeouts or 5xx).<br>2. Requeue job with exponential backoff and increment retry count.<br>3. If retries exceed the maximum threshold, route to DLQ.<br>4. Update `AI_SUMMARIES` status to `FAILED` with error metadata. |
| Error Scenarios     | - Retry enqueue fails returns internal error.<br>- DLQ unavailable returns internal error.                                                                                                                                                                |
| Constraints         | - Exponential backoff is required for retries.<br>- DLQ routing occurs after max retries are exceeded.                                                                                                                                                    |
| Acceptance Criteria | - Transient failures are retried with backoff.<br>- Exhausted retries end in DLQ with `FAILED` status.                                                                                                                                                    |
