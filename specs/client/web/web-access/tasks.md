Use installed libraries: RHF owns transient form drafts, Zod owns validation, Query owns asynchronous operation/resource state, and a typed identity controller owns access transitions/generation. Avoid a second competing identity cache or global form store. Adapter factories are selected by composition, never by UI. Features cannot import app, another feature's internals or backend/worker modules. `shared` imports neither features nor app. No HTTP adapter or transport is needed.

The app must not import files from `specs/` at runtime. Translate approved design into maintainable React components; do not copy the prototype DOM renderer/fake wholesale. Copy only needed approved static assets and synthetic fixture content to owned app paths. Lucide `Eye`/`EyeOff` supply consistent accessible password controls; logos remain approved SVGs.

Planned order: `WA-T01 → WA-T02 → WA-T03 → WA-T04 → WA-T05 → WA-T06`. Each slice includes the model/service/UI/tests needed for its observable outcome. Do not complete disconnected architectural layers before making a slice usable.

## Risks, Exclusions and Approval-Sensitive Changes

1. **Prototype behavior is not a production architecture.** Rebuild from client models/services and acceptance tests; keep fake adapters behind injected interfaces. Preserve approved visual behavior while correcting implementation defects.
2. **Session data may reappear through races/cache/history/storage.** Test deferred results, query cleanup, malformed/denied storage, Back/reload and pending logout before private rendering. A local UI guard is not provider authorization.
3. **Mutation responses may be lost after commit.** Keep confirmed/uncertain outcomes distinct, prohibit automatic replay and test explicit recovery. Integration must separately resolve provider mappings/idempotency/credential storage.
4. **Evidence has revision limits.** Prototype r1 had 96 matrix checks plus two dialogs; prototype r2 was human-approved after minor UI/cache changes without a fresh full browser replay. React must obtain its own current evidence. Browser zoom and assistive-technology evidence remain required, not implicitly approved by design review.
5. **Scope boundaries must survive composition.** No real API, endpoints, HTTP adapters, backend/workers/infra changes, native code, OTP/recovery/settings operations, discovery/workshop implementation, tickets/payments, member actions, notifications, reports or analytics. Never import provider entities or mirror their database schema.
6. **Material changes require approval.** Changes to business behavior, role/tenant powers, route semantics, persistent auth policy, global UI or bundle scope stop dependent work for impact review. Routine in-scope file organization and defect fixes do not introduce per-file gates.
