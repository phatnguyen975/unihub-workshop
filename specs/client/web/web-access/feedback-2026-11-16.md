# Web Access UI Feedback Revision 3

- **Status:** Requested corrections implemented and automated verification passed; final human review pending.
- **Authority:** Human feedback on 2026-11-16 explicitly authorizes this scope of corrections.
- **Dependencies:** Preserve approved spec 1 / prototype 2 / tasks 1 / UI baseline 6 as historical records. This scoped UI amendment is not a new global approval or MOCK acceptance.

## Requested Behavior

1. Center close icons in a borderless transparent target; show a subtle circular hover/focus background. Keep footer dialog copy as the existing placeholders.
2. Replace the ambiguous open-ring loader with an explicit named progress treatment. Checking/restoring, signing out and recoverable failures remain distinct; failure keeps recovery actions rather than indefinite loading.
3. Account popup uses a name larger than action labels, small email, ellipsis for overflow with full text available, and leading Lucide action icons.
4. Organizer sidebar is scoped to the management workspace, never home or public workshop browsing. The account-menu management entry goes to existing `/organizer/workshops`; no new analytics/dashboard capability is introduced.
5. Desktop sidebar is an inset rounded card. At narrow widths a header icon next to the logo opens a centered modal navigation with a dimmed backdrop, focus containment, Escape and close/selection dismissal. No separate menu-only row.
6. Shorten temporary-password helper copy while retaining existing validation rules.
7. Use auto-dismissing success notifications. Keep field errors, uncertain password outcomes, unavailable restoration and unconfirmed logout persistent/actionable. Local removal must never claim service revocation.
8. Language trigger/options use normal weight; background indicates the active option.
9. Compact footer vertical spacing while retaining usable targets. Center short-page content within available main space; long pages scroll naturally.
10. Remove the redundant Signed In prefix from role boundary identity text in both locales.

## Impact and Review

This revision affects the React shell, access state presentation, notifications and localized copy. It supersedes only the listed capability-local presentations for the review build. Reusable close-target, footer, account and navigation changes are proposed amendments to baseline rules WEB-UI-002/003/005/006/007/013/014; their final shared baseline/foundation promotion remains pending review. No automatic rewriting of previously approved artifacts or golden screenshots is authorized.

Acceptance scenarios: public home/public workshops without organizer sidebar; desktop management card; narrow header menu and modal dismissal; account ellipsis; centered footer-dialog close target; normal-weight locale choices; readable loading/progress and error recovery; toast expiry without repeating on navigation; compact centered short-page layout; unchanged password/security/role semantics. Retain all existing functional regressions and run fresh browser/visual evidence before presenting for review.

## Implementation Result

All requested presentations are implemented in the React MOCK build. Success notifications use `react-hot-toast` 2.6.1 with a 4-second duration and one-shot message consumption. Persistent errors and uncertain outcomes retain their recovery controls. Password helper copy is shorter without relaxing uppercase/lowercase/number/special-character validation. The former C-shaped graphic was an open-ring spinner, not content; a named progress bar replaces it.

Fresh evidence: 51 unit/component tests and 68 Chromium browser tests passed, including regressions for route-specific workspace chrome, modal navigation, account ellipsis, close-button geometry, locale weight, short-content centering and toast expiry. Actual desktop/mobile screenshots were viewed. See [Feedback Verification](verification.md#feedback-revision-3-2026-11-16) for commands, limitations and technical review. This does not grant human acceptance or promote the proposed shared baseline amendments.
