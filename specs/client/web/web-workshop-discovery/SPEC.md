## Actors and Preconditions

Visitors and signed-in students browse the same public catalog. Public access remains available when users enter without a session. Access owns session restoration, sign-in, temporary-password replacement and role behavior. Only a student can continue to a future student registration flow. Public discovery never requires student activation to view catalog or details.

`WS-02` provides the discovery part of `WJ-01` and `WJ-02`. Users enter through the home page or Discover navigation at `/workshops`, or open a public detail link directly. They leave with a workshop selected, return to their catalog results, or sign in and resume the selected detail.

## Data, Action and Error Requirements

`workshops` owns the client projections and injected service interface. App composition selects the fake. The feature may share the public identity entry point through app composition and uses existing shared UI and localization. Scenarios reset deterministically using synthetic data and controllable failure/delay outcomes.

| Client Need          | Data or Behavior                                                                                                                                                                                                                                                                             |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Catalog read         | Trimmed query, optional Free/Paid, optional complete local calendar date range and optional page continuation. Return ordered summary items and whether a next page is available. Support deterministic previous-page navigation without requiring the provider to expose a previous cursor. |
| Public summary       | Stable identity and URL-safe slug, title, start/end timestamps, IANA event timezone, location, price amount/currency, price category, nonnegative available seat count, optional local cover image.                                                                                          |
| Detail read          | Detail URL uses the public slug at proposed route `/workshops/:slug`. Add optional description, ordered speakers with name and optional bio/portrait, and optional local brochure with accessible title and asset reference.                                                                 |
| Featured read        | Ordered subset of up to three published summaries selected by the fixture.                                                                                                                                                                                                                   |
| Failure and recovery | Distinguish invalid input, transient unavailable/offline and unavailable detail. Invalid or stale page state recovers to the first page. Use distinct fixtures for slow and out-of-order reads, empty data, no matches, free, paid, full, optional content missing, and unavailable detail.  |

The model defines UI needs. The approved detail response currently has no dedicated brochure field. Keep the synthetic asset in MOCK and record that gap for a future integration specification. Date conversion also needs explicit mapping at integration because the public contract accepts UTC bounds and MOCK filters calendar dates in each event timezone. Neither gap delays the MOCK design.

## Platform, Security and Offline Concerns

- Use mobile-first base CSS or unprefixed Tailwind. Enhance at wider breakpoints. Review 320, 390, 768 and 1440 px, and exercise the shell at 650/651 px when checking new routes. Include long authored content, EN/VI and both themes.
- Provide programmatic names for search, calendar, carousel, pagination and brochure actions. Use visible focus, keyboard operation, Escape and focus return for dismissible controls, and understandable result/error announcements. Respect reduced motion. Review real browser zoom and assistive technology as web acceptance evidence.
- Allowlist intent paths and query keys with route-specific validation; reject external, malformed and unexpected destinations. Render authored content as text and brochure references from controlled local fixtures. Public reads cannot reveal nonpublic fixture records or trigger writes.
- Keep review scenario controls outside product content, using a development-only import path. Verify standard build output and browser behavior without the review controls. The MOCK journey requires zero live API calls and uses no real personal data or credentials.

## Out of Scope and Dependencies

No hard capability prerequisites. The proposed implementation reuses accepted access artifacts (spec 1 / prototype 2 / plan 1, accepted implementation `72d1160`). App composition replaces the public catalog placeholder and adds the exact detail route and safe-intent validation needed for this slice. `web-free-registration` and `web-paid-registration` consume discovery outputs under their own bundles. Provider and shared fixture relationships carry no MOCK build prerequisite.

Account activation and recovery, organizer publishing, operational views, booking, payment, tickets, room diagrams, live seat updates, real search ranking, durable offline data and API integration are outside this slice.

The [approved MOCK bundle](tasks.md) records the compatible artifact revisions. Technical verification and human MOCK acceptance are later records.
